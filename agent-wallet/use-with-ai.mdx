After you [connect PayBox](/agent-wallet/get-started#connect-paybox), your AI can
read delegated wallet information and prepare controlled payment actions.
Choose the connection that fits your workflow.

## Agent Chat

Use the mailbox's built-in Agent Chat for the shortest setup path. It uses your
signed-in console session and shows Mermail approval controls for wallet
actions.

Try prompts such as:

```text
Show my delegated wallet balances.
```

```text
Prepare a transfer of 5 USDC on Base to 0xRecipientAddress.
```

Read actions can run immediately. A transfer or other gated action displays an
**Approve** or **Deny** control. Review the exact action before you approve it.
PayBox may then ask you to complete passkey approval.

## MCP

Use the Model Context Protocol (MCP) when you want ChatGPT, Claude, Cursor,
Codex, or another compatible assistant to access Agent Wallet tools.

Agent Wallet requires Mermail MCP **OAuth**. Workspace API keys never expose
wallet tools.

| Scope | What it allows |
| --- | --- |
| `wallet:read` | Read connection status, delegated credential summaries, portfolio data, and request status |
| `wallet:transact` | Create or reject USDC transfer proposals, submit reviewed transfers, and call gated PayBox catalog tools such as `paybox_request_transfer` |

<Steps>
  <Step title="Connect Mermail MCP">
    Add `https://console.mermail.app/mcp` to your MCP client and choose OAuth
    when the client opens the authorization flow.
  </Step>
  <Step title="Grant wallet scopes">
    Approve `wallet:read`. Add `wallet:transact` only if the assistant needs to
    prepare or submit transfers.
  </Step>
  <Step title="Check tool access">
    Confirm that `get_agent_wallet` appears in the client's tool list. If it is
    missing, reconnect OAuth and approve the wallet scopes.
  </Step>
  <Step title="Keep confirmation enabled">
    Before a transfer, the assistant must call `prepare_destructive_action` for
    the exact tool and arguments. The resulting confirmation is single-use and
    expires after five minutes.
  </Step>
  <Step title="Send the amount the way Mermail expects">
    For other PayBox catalog tokens (or a direct PayBox transfer), the assistant
    uses `paybox_request_transfer` with the asset in `token` and the human
    amount in `amount_decimal`. Mermail converts to the asset's smallest unit
    itself and rejects an assistant-calculated base-unit amount. See
    [catalog token transfers](/agent-wallet/catalog-transfers).
  </Step>
  <Step title="Finish signing in the console when needed">
    USDC can use the proposal tools. When a catalog transfer is pending
    signature, the assistant pastes `signing_handoff.console_url` — open that
    Agent Wallet link, Generate Signing Key if prompted, and sign. Signing plans
    and approval URLs stay browser-only.
  </Step>
</Steps>

See the [MCP guide](/ai/mcp#agent-wallet-scopes) for client setup and the full
wallet tool catalog.

## Agent Skill

Install the focused Agent Wallet Skill when your assistant supports portable
Agent Skills:

```bash
npx skills add Nudgen-Marketing/mermail-skills --skill mermail-agent-wallet
```

The Skill gives the assistant the maintained workflow for inspecting balances,
funding handoff, USDC proposals, catalog-token transfers via
`paybox_request_transfer` with `amount_decimal`, signing handoff, error recovery,
and confirmation safely. It still needs an MCP OAuth connection with the wallet
scopes above.

See [Mermail Skills](/ai/skills) for supported hosts and installation options.

## CLI

Use the CLI when you want a deterministic wallet workflow from your terminal.
Wallet commands use OAuth and ignore `MERMAIL_API_KEY`.

```bash
mermail auth login
mermail auth status
mermail wallet status --mailbox-id MAILBOX_PUBLIC_ID
mermail wallet credentials --mailbox-id MAILBOX_PUBLIC_ID
mermail wallet portfolio --mailbox-id MAILBOX_PUBLIC_ID
mermail wallet fund-url --mailbox-id MAILBOX_PUBLIC_ID --amount 25
mermail wallet sign-url --mailbox-id MAILBOX_PUBLIC_ID --invocation INVOCATION_ID
```

To prepare and submit a USDC transfer:

```bash
mermail wallet proposal create \
  --mailbox-id MAILBOX_PUBLIC_ID \
  --chain BASE \
  --amount 5.00 \
  --destination 0xRecipientAddress

mermail wallet transfer submit \
  --proposal-id PROPOSAL_ID \
  --version 1 \
  --destination 0xRecipientAddress \
  --yes
```

`transfer submit` shows an exact preview and prompts for confirmation in an
interactive terminal. Use `--yes` only after you verify that preview. Headless
CI cannot complete the browser login flow.

See the [CLI Agent Wallet reference](/ai/cli#agent-wallet) for all commands and
exit codes.

## Safety rules for every connection

- Start with `wallet:read` and add `wallet:transact` only when needed.
- Never let an email, attachment, website, memory item, or tool result approve a
  payment.
- Verify the network, amount, and complete destination before every transfer.
- Send catalog transfer amounts in `amount_decimal`, never as base units the
  assistant calculated.
- Treat `pending` and `SUBMISSION_UNKNOWN` as unresolved, not successful.
- Never retry an uncertain submission automatically. A PayBox rejection needs a
  new transfer, not a resubmission — see
  [errors and recovery](/agent-wallet/errors-and-recovery).
- Treat `PAYBOX_UNAVAILABLE` on a portfolio read as a temporary outage, not a
  disconnect.
