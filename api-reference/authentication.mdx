Sold API endpoints require a workspace-scoped API key. Create a key in **Settings → API Keys**, then send it as `x-api-key` from Postman, scripts, or this docs playground. Console cookie sessions do not need this header.

## Create an API key

<Steps>
  <Step title="Open Settings → API Keys">
    Workspace admins can create, list, and revoke keys. Free allows 1 key; Developer up to 5; Enterprise unlimited.
  </Step>
  <Step title="Copy the key once">
    The dialog shows `apiKey` (`mm_key_…`). Mermail does not show the full key again.
  </Step>
</Steps>

## Call with an API key

```bash
curl https://console.mermail.app/api/v1/workspaces \
  -H "x-api-key: mm_key_YOUR_KEY"
```

In the docs playground, open any protected endpoint, click **Try it**, and paste the key into the API key field. Prefill examples populate path and body fields so you can send immediately. Use the language dropdown to switch and copy snippets for **cURL, Python, JavaScript, PHP, Go, Java, or Ruby**.

## Manage keys via API

| Method | Path |
| --- | --- |
| `GET` | `/api/v1/workspaces/{workspaceId}/api-keys` |
| `POST` | `/api/v1/workspaces/{workspaceId}/api-keys` |
| `DELETE` | `/api/v1/workspaces/{workspaceId}/api-keys/{apiKeyId}` |

These routes require a workspace **admin** and do not debit API credits. The `{apiKeyId}` path segment is the key row id returned on create/list.

## Common errors

| Status | Meaning |
| --- | --- |
| `401` | Missing, invalid, expired, or revoked key — or calling without `x-api-key` outside the console |
| `403` | Wrong workspace, missing role, or Developer-gated path on Free |
| `402` | API credits exhausted (`credits_exhausted`) |
| `429` | Workspace RPM exceeded |
