Before you begin
Prepare once

Gather access and safe test data

You can complete the setup faster when the right people and test accounts are ready.

Goal

Prepare everything needed for the five setup jobs.

Do not use real customer secrets, payment details, or confidential attachments during testing.

Before you begin
  • Mermail admin access for mailbox, domain, and support-rule configuration.
  • A Mermail mailbox address that can receive a forwarding confirmation.
  • Gmail or Outlook settings access, plus administrator approval if external forwarding is blocked.
  • DNS access and a Developer or Enterprise workspace for a custom domain.
  • Three approved knowledge files such as shipping, returns, and invoice guidance.
Check it worked

You are ready when you can open the Mermail inbox, email-provider settings, workspace settings, and DNS dashboard.

Steps
  1. Choose your support address.
    Example: existing support@example.com or new support@mail.example.com.
  2. Choose your forwarding boundary.
    Start with messages sent to the support address—not the entire personal inbox.
  3. Create two safe test messages.
    One should match the forwarding rule. One should be excluded.
  4. Prepare one urgent example.
    Example: “Our production order is blocked today.”
  5. Prepare one normal example.
    Example: “Please send another invoice copy.”
Troubleshooting

Missing admin access? Ask an existing workspace admin, email administrator, or DNS owner before continuing. Do not work around organization security policy.

Auto-forward Gmail
Setup job 1A

Forward selected Gmail messages

Use a Gmail filter so Mermail receives support mail without receiving the whole inbox.

Gmail path · Settings → See all settings → Forwarding and POP/IMAP
Before you begin

Have the Mermail mailbox address ready. Ask your Google Workspace admin whether external forwarding is allowed.

Steps
  1. Add a forwarding address.
    Enter the Mermail mailbox and confirm the Gmail prompts.
  2. Approve the request.
    Open the verification message in Mermail and follow the confirmation link.
  3. Keep account-wide forwarding disabled.
    A selective filter can still use the verified address.
  4. Create a positive filter.
    Use Gmail search options, for example to:support@example.com.
  5. Choose Forward it.
    Select the Mermail address, save the filter, and send two new tests.

Check it worked
  • The matching new message appears in Mermail.
  • The excluded message stays only in Gmail.
  • The original sender and subject are readable.
Troubleshooting

Address unavailable: complete the verification link in Mermail.

Everything forwards: disable account-wide forwarding and keep only the selective filter.

Human takeover: if someone replies directly from Gmail, Mermail permanently stops AI processing for that entire thread. Continue the thread in Gmail after takeover.

Auto-forward Outlook
Setup job 1B

Redirect selected Outlook messages

Use an Outlook rule with Redirect to so Mermail sees the original customer as the sender.

Outlook path · Settings → Mail → Rules → Add new rule
Before you begin

Have the Mermail address ready. Microsoft 365 administrators may block automatic forwarding outside the organization.

Steps
  1. Create a named rule.
    Example: “Redirect support mail to Mermail.”
  2. Add a narrow condition.
    Use recipient, sender, subject, or another supported field.
  3. Add sensitive-mail exceptions.
    Keep payroll, password resets, legal, and private mail outside the rule.
  4. Select Redirect to.
    Enter the Mermail mailbox. Redirect preserves the original sender identity.
  5. Save and test.
    Send one matching and one excluded new message.

Check it worked
  • The matching new message reaches Mermail.
  • The excluded message does not reach Mermail.
  • Mermail shows the original customer sender.
Troubleshooting

No delivery: ask your Microsoft 365 admin whether outbound automatic forwarding is blocked.

Wrong sender: use Redirect to instead of Forward to.

Human takeover: replying directly from Outlook permanently hands the entire thread to a human and stops later Mermail AI processing.
Other providers: use the Mermail forwarding guides for iCloud Mail, Proton Mail, Yahoo Mail, and Lark Mail.

Custom email domain
Setup job 2A

Add and verify your subdomain

Use a dedicated subdomain so Mermail does not replace the MX records for your organization’s existing root email.

Mermail path · Workspace Settings → Domains → Add domain
Before you begin
Developer+

Plan includes custom domains.

Admin

Workspace admin access.

DNS

Permission to publish records.

Steps
  1. Choose a dedicated subdomain.
    Use mail.example.com or support.mail.example.com. Do not use example.com.
  2. Add the complete subdomain.
    Mermail provisions the domain and returns the required DNS records.
  3. Publish every returned record.
    Copy type, name, value, and MX priority exactly. Do not guess SPF, DKIM, MX, or DMARC values.
  4. Wait for DNS propagation.
    Check that your DNS provider did not append the parent domain twice.
  5. Click Verify in Mermail.
    Retry safely after correcting a record or waiting for propagation.

Troubleshooting

Rejected domain: use a subdomain with at least three labels.

Still pending: compare every DNS field, wait for propagation, then verify again.

Name duplicated: use the relative host format expected by your DNS provider.

Do not use a bare root domain. Mermail rejects it, and replacing root-domain MX records could disrupt existing company email.

Setup job 2B

Create and test the support mailbox

After the domain is verified, create a customer-facing mailbox and test delivery in both directions.

Mermail path · Mailboxes → New mailbox → Select verified domain
Before you begin

The custom domain must show verified. Choose a clear username such as support.

Steps
  1. Open New mailbox.
    Select the workspace that owns the verified domain.
  2. Select the custom domain.
    Choose mail.example.com from the available domains.
  3. Enter the username and name.
    Example: support@mail.example.com and “Customer Support.”
  4. Send an inbound test.
    From an outside account, email the new address and confirm it appears in Mermail.
  5. Send an outbound reply.
    Confirm the recipient, sender address, display name, subject, and thread.

Task triage
Setup job 3

Test the default email triager

Every mailbox has a protected triager that prepares inbound customer replies as drafts for human review.

Mermail path · Mailbox sidebar → Task triager → Default email response triager
Before you begin

Use a safe external account to send a new customer-style message into the mailbox Inbox.

Steps
  1. Open Task triager.
    Find Default email response triager. It is created automatically.
  2. Send a new inbound test.
    Ask a clear support question, such as an order-status request.
  3. Wait for the prepared draft.
    The triager uses the thread, mailbox context, and built-in customer-care instructions.
  4. Open the draft and Agent.
    Review the linked triager conversation and the generated reply.
  5. Edit before sending.
    Verify customer identity, order facts, promises, dates, links, and attachments.

  • The inbound message appears in Inbox.
  • A linked reply appears in Drafts.

No draft: confirm the message is new, in Inbox, and not bulk or automated mail.

Wrong facts: correct the draft and improve trusted Knowledge instead of sending it unchanged.

Current limitation: a custom instruction-only mail triager does not run those instructions on received or sent mail. Use the protected default triager for inbound reply drafts. Custom instructions run for supported Google Calendar triagers.

Support agent rules
Setup job 4

Add labels and precise urgency rules

Use current console rules to organize requests and highlight messages that truly need attention today.

Mermail path · Mailbox Settings → Custom labels and Urgent email detection
A. Custom labels
Goal: make each label change how the team handles the message.
  1. Open Manage labels.
    Select Add label.
  2. Name one support decision.
    Examples: Order status, Invoice, Damaged shipment, VIP.
  3. Write a specific rule.
    Example: “Damage, shortage, missing cartons, or unusable goods.”
  4. Save and enable detection.
    New inbound mail will be checked against the rules.
Label: Damaged shipment Rule: Customer reports damage, shortage, missing cartons, or goods that cannot be used.
B. Urgent email detection
Goal: reserve urgent badges and stronger alerts for work that needs attention today.
  1. Enable urgent detection.
    Built-in defaults apply when the custom field is empty.
  2. Add custom rules only when needed.
    Custom rules fully replace the built-in defaults.
  3. Name concrete signals.
    Use sender, domain, subject, deadline, outage, or operational impact.
  4. Save and test two messages.
    One should be urgent and one should remain normal.
Urgent: - Production is blocked today. - A payment failure blocks order release. - A VIP customer has a same-day deadline. Not urgent: - Routine invoice-copy requests. - General catalog questions.
Check it worked

The damaged-order test receives the correct label and urgent badge. The routine invoice-copy test is labeled but not urgent.

Troubleshooting

Too many matches: replace broad words like “important” with concrete senders, subjects, deadlines, and business impact.

Rules organize and prioritize. They do not assign an owner, start an SLA timer, or authorize a refund, replacement, credit, or shipment change.

Before you begin

Prepare current, approved documents with an owner and effective date.

Steps
  1. Open the Knowledge tab.
    The panel checks or prepares your secure knowledge connection.
  2. Connect or reconnect when prompted.
    Wait until the status is active before uploading.
  3. Upload one focused document.
    Start with a shipping, returns, invoice, or wholesale policy.
  4. Confirm the indexed document.

  5. Ask the Agent a test question.
